# AGENTS.md — 文档标准

[English](AGENTS.md) | 中文

本文件定义 TelnetKit 的文档层级、归属、写作规则与字数上限。归属与校验交给 [telnetkit-doc](../.agents/skills/telnetkit-doc/SKILL.md)。常驻规则见[根 AGENTS.md](../AGENTS.md)。

## 文档结构

这些规则适用于面向人的文档，不适用于 vendored 上游文件——后者保持上游形态。

把每份范围内的文档归为教程或参考。教程有一条通往结果的既定路径，只引入每一步所需的内容；[README 快速开始](../README.md) 是唯一的教程。参考界定一个查阅范围，陈述当前行为而不设教学顺序。教程与参考内容体量都较大时须拆开；只有一部分较小时就地标注。

文档的主题决定它的范围：按该主题自身的细节层级描述，按用途与职责描述直接子项，更低层的细节链接到其归属的下级文档。参考只允许对自己的主题穷尽。图可以承载时序或组成，但绝不承载正文必须同时陈述的规则。

按此顺序写作：在层级表中定位文档；确定其允许的细节层级；选择教程或参考；按前置依赖排列教程概念；下沉属于下级的细节；把低层解释替换为指向其归属方的链接。

## 层级分类：一个事实一个家

每个事实只有一个家：承担该职责的层级。别处链接过去。同一陈述出现在两个层级，就是其中一个层级的缺陷。

| 层级 | 职责 | 不该出现在那里 |
|---|---|---|
| [根 AGENTS.md](../AGENTS.md) | Agent 每次会话都需要的常驻规则：身份、命令、不可协商约束、约定，每条一至三行并链接受其归属文档 | 完整示例、需求细节、API 目录、任何从被链接归属方复述来的内容 |
| [docs/architecture.md](architecture.md) | 设计的有序地图：分层、所有权、并发模型、事件流、扩展点；修改 `Sources/` 前必读 | 逐类型的 API 契约（→ public-api.md）、需求编号与验收标准（→ PRD.md）、决策历史 |
| [docs/public-api.md](public-api.md) | 调用方契约：每个公开类型、方法、属性与 enum case 及其前置条件、失败、顺序与取消行为 | 需求与优先级（→ PRD.md）、内部设计（→ architecture.md）、测试清单（→ 测试文件） |
| [PRD.md](../PRD.md) | 需求：目标、用户故事、带编号的功能与非功能需求、验收标准、测试用例清单、Demo 范围、里程碑、风险 | 作为契约存档的 API 签名（→ public-api.md）、架构理由（→ architecture.md） |
| [docs/testing.md](testing.md) | 测试方案：环境、框架、在 macOS 与各模拟器上如何运行每个套件、质量门槛、CI 矩阵 | 需求编号与验收标准（→ PRD.md）、单个测试的设计说明（→ 测试源码） |
| [README.md](../README.md) | 使用方契约：库做什么、安装、可运行的快速开始、支持平台、已知限制、安全立场 | 贡献者流程、内部设计、需求可追溯性 |

## 写作规则

- **当前行为用现在时。** 未实现的设计标记为 `Designed` 并写成需求，依据[设计状态规则](../AGENTS.md#design-status)。历史留在 commit、pull request 与 PRD 里程碑表中。
- **每段一个物理行。** 使用编辑器软换行；代码块、表格与列表结构保持原有格式。
- **一个术语一个家。** 术语只在[术语表](public-api.md#glossary)定义一次并复用。同一概念出现第二个名字即为缺陷。
- **点出机制。** 写出确切的函数、类型、文件、字节序列或命令：`TelnetChannelHandler` 在回调内拷贝 buffer，而不是「该层做了归一化」。
- **字节级结论要给出字节。** 用十六进制写出线上字节与对应的 Swift 值，并写在与证明它的测试同段。
- **写完整契约，不写推理过程。** 保留行为、失败、时序、所有权、模态、例外与后果；删除推导路径、测试走查、评审历史，以及对代码或被链接归属方的复述。
- **需求必须可测。** PRD 需求要给出一个具名测试能断言的可观测结果；不要加没有测试能区分的需求。
- **代码映射要穷尽。** Swift 值与线码的映射必须穷尽；对未匹配的码要写清名字，不能写「以及其他」。
- **不做状态装饰。** 不要在标题上标注「已实现」或「WIP」；状态由设计状态规则与里程碑表承载。
- **慎用强调。** 加粗只用于改变行为的那一句，不用于整组规则。

## 字数上限

下表上限是护栏，不是削减目标。用 `wc -w` 统计文件词数，文档处于上限以内时保留至少 5% 余量。

| 文档 | 上限（词） |
|---|---|
| `AGENTS.md` | 1,400 |
| `docs/AGENTS.md` | 1,700：本文件负责双语配对机制与九个层级的归属表 |
| `docs/architecture.md` | 2,100：平台与传输层决策表以及路径事件流无法在不丢失设计契约的前提下下沉 |
| `docs/public-api.md` | 3,200：调用方契约对每个公开符号穷尽，成员表格的一行所占词数无法在不丢契约的前提下下沉 |
| `docs/testing.md` | 1,400：每层一个命令块加 CI 矩阵 |
| `README.md` | 900 |
| `.agents/skills/*/SKILL.md` 下的 skill | 1,400 |
| `PRD.md` | 不设上限：它拥有需求细节 |

文档超过上限时，按此顺序执行，并在第一个奏效的步骤停下：

1. **下沉**属于其他层级的内容，必要时留一行链接。
2. **精简**确属本层但可写得更短的内容。
3. **上调**上限——仅当所需内容确实需要这些篇幅，并在同一次变更中说明理由。上限过低本身就是文档缺陷。

## 双语配对

每份面向人的文档都有一个英文原本和一个中文对照版：`foo.md` 与并列的 `foo.zh.md`，因此 `AGENTS.md` 的对照版是 `AGENTS.zh.md`。[PRD.md](../PRD.md) 是唯一的例外：它的正本是中文，英文对照版为 `PRD.en.md`，因为中文是需求源语言。两侧在同一次变更中落地。[README.md](../README.md) 与 [README.zh.md](../README.zh.md) 是参考配对。

配对双方保持相同的标题序列、列表与表格结构、代码块与链接目标，以及相同的物理行数，使评审者可以逐行对齐比较。含标识符的行可能不同，因为相对链接是按文件自身目录解析的，而中文文件名与英文原本并列。用以下命令计数：

```sh
wc -l AGENTS.md AGENTS.zh.md
```

翻译规则：

- 翻译正文、标题、表格文字与代码注释。绝不翻译代码标识符、命令、路径、线上字节序列、`TelnetError` case 或链接目标。
- 一个概念在中文里只用一个术语并复用：选项 (option)、协商 (negotiation)、子协商 (subnegotiation)、命令 (command)、事件 (event)、连接 (connection)、会话 (session)、调用方契约 (caller contract)、常驻规则 (standing orders)。
- 两种说法承载同一命题时优先用更短的中文分句。不要为了凑行数而灌水，改为改写英文那一行。
- 一次更新两侧。一侧为真而另一侧过期，是配对的缺陷，不是翻译欠账。
- 不增加第三种语言文件。要引入中文以外的语言，先在本文件记录决策。

未配置翻译工具时，手工产出对照版，并把逐行表层核对与行数比较作为证据留下。绝不允许合入缺少一侧的配对。

## 冗余清单

在报告文档完成之前，先排查这些：

- 一条规则出现在两个层级，或契约紧挨着拥有它的链接被复述。
- 设计中的行为被用现在时写成已观测到的事实。
- 手工复述的清单：API、测试或需求列表被复制而不是链接。
- 推理过程：推导步骤、分支证明、测试走查、被否决的方案。
- 段落墙：一段里塞了多条规则和旁注。
- 强调通胀：通篇加粗导致什么都不突出。
- 实现后的规格腔：「应该」、「将来需要」，或把验收清单留在已经描述既成行为的参考里。
- 没有解释的魔法数字：没有所有者和单位的阈值、超时或缓冲大小。
