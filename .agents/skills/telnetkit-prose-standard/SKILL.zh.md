# TelnetKit 行文标准

[English](SKILL.md) | 中文

## 概要

写到足以保住契约，然后删掉推理过程、重复与装饰。契约是调用方或被调用方所依赖的义务、不变量、前置条件、后置条件或兼容性承诺。本 skill 负责句级判断与必要的覆盖范围；归属、层级、字数与校验用 [telnetkit-doc](../telnetkit-doc/SKILL.md)。

## 输入与模式

必须有明确范围：具名文件、一份 diff，或一个具名符号。范围缺失时报告并停止。

接受 `mode: automatic | interactive`，默认为 `automatic`。自动模式下直接应用明确的修改，对真正的边界情形只报告不追问。交互模式下把同类段落归到一条原则下，给出两三个可行版本，推荐其中一个，并说明事实差异。不要拿更弱的选项凑数。

模式控制的是提问与否，不改变写权限：评审只报告不编辑，明确要求修复时才应用清晰的改动。

任何范围下都把 `Sources/CLibTelnet/` 排除在编辑之外。

## 保全完整命题

编辑一段文字之前，先列出它的命题。保留每个相关的施动者与动作、条件与顺序、模态（如必须、可以）、否定性保证与例外、所有权、副作用、失败方式与后果。

只有当所有事实分句都存活且结果更清楚时，才删除形容词、重复或叙述。更短的段落并不自动更好。

在使用处保留完整的本地契约：会发生什么、会失败什么、谁拥有资源、调用方必须做什么。架构、理由、算法、历史与扩展示例链接到其归属方。一个解释只有一个家；关键契约事实可以在本地重复。

当省略某条不显然的理由可能导致误用（例如为什么 buffer 是拷贝而不是持有）时，保留该理由。否则只陈述后果并链接原因。

## 按位置要求的覆盖范围

这不是一次统一缩短。当代码与类型无法承载下述契约时就补上，已经承载时就保持沉默。

- **公开文档注释。** 写明结果、按 `TelnetError` case 分类的抛出条件、事件流的结束条件、所有权、转义与行尾转换等线缆侧影响、顺序与取消行为。只读生成 interface 的读者也必须知道何时调用该成员、失败意味着什么。
- **内部注释。** 为读者无法就地看到的结构做定位：EventLoop 所有权、回调生命周期规则、选项账本与观测事件的关系，以及任何可能被重构静默破坏的不变量。删除控制流叙述与对下一行的复述。
- **模块级注释。** 写明文件的职责、依赖与不显然的设计选择，并用链接指向 [architecture.md](../../../docs/architecture.md) 获取理由。
- **测试。** 只解释不显然的测试设计：为什么需要某个夹具、间接观测或平台适配。删除走查与断言清单。
- **README。** 覆盖库做什么、支持平台、安装、可运行的快速开始、已知限制与安全立场。引用调用方所依赖的行为，而不是转述接口参考。
- **Skills。** 写明护栏与范围限制，工作流保持简短，规则链接其归属文档而不是复述。
- **诊断与日志信息。** 写明失败主体、被违反的规则，以及在不显然时给出修正方式；绝不包含载荷字节或对端提供的值。
- **错误。** `TelnetError` case 的文档注释说明什么条件产生它、调用方能做什么；不要复述 C 错误码。

## 使用前需核对的术语

把 `contract`、`boundary`、`surface`、`seam`、`layer`、`shape` 当作需要核对的词，而不是禁词。先问更精确的词是否更能点出主体：写 `the event callback`、`the TCP connection`、`the public API` 或 `TelnetChannelHandler`，而不是 `the boundary` 或 `the layer`。`contract` 只用于真实义务，`boundary` 只用于字面意义上的进程、线缆或信任边界。

严格使用[术语表](../../../docs/public-api.md#glossary)中的词：`option`、`negotiation`、`subnegotiation`、`command`、`event`、`connection`、`session`、`NVT`。不要为其中任何一个另造名字，也不要把连接称为会话。

点出机制。「解析层会剥掉它」不可用；「`TelnetProtocolCore` 去掉 `IAC` 序列，只在 `.data` 中发出应用字节」才是事实。

## 工作流

1. 确认范围、模式，以及拥有受影响事实的文档。
2. 判断一段文字之前，先读拥有它的代码、测试或上游头文件。
3. 把每个候选归类为保留、补充、精简、恢复或重构。按语义判断，不按长度判断。
4. 只在任务授权编辑时应用明确的改动，并先更新归属方再更新派生文档。
5. 学到一条规则后，重读一段同类文字，并把规则同样应用过去。
6. 执行 [telnetkit-doc](../telnetkit-doc/SKILL.zh.md#校验) 中的检查；当可视字符串或文档所述行为发生变化时，另跑 `swift test`。
7. 报告检查过的范围、明确的改动、有意保留的内容，以及每个延后处理的用例及其原因。
